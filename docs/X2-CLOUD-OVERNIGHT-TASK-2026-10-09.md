# X2「会找」云端夜间验证任务（2026-10-09）

> **执行对象：Codex / Work 云端环境**
>
> **任务性质：自主执行实验。不是调研报告任务。**
>
> **核心 KPI：真实影视素材 Top3 镜头检索成功率。目标 ≥90%，但不得伪造或修改统计口径。**

## 0. 目标

继续 `video-moment-validation` / 数智博主 POC。

在真实《潜伏》素材上，验证“根据结构化分镜画面需求，从原片找到正确镜头”的「会找」能力。

最终成功定义：

> **正式盲测中，每条分镜需求返回 Top3；Top3 至少有 1 个真正满足需求的原片镜头，则该题成功。成功题数 / 有效盲测题数 ≥90%。**

90% 必须来自真实素材人工看片/听音验证。程序运行成功、模型自评、相似度、Q1–Q5 调参结果均不能代替正式成功率。

## 1. 环境要求

今晚所有新增安装、模型运行、索引、批量实验和复测**优先在云端完成**。

- 不要依赖用户本地 Mac 长时间运行。
- 今晚不依赖本地 AntiGravity / AGY。
- 云端自行 clone、建隔离环境、安装依赖/FFmpeg、运行模型、建索引、修改代码、测试、复测、保存日志、提交 Git。
- 云端不要因用户 Mac 为 Apple Silicon 而优先选择 MLX；根据云端硬件选择合适后端。
- 遇到兼容性问题先自行寻找替代实现，不要停下来等用户。

## 2. 真实素材

用户会把《潜伏》真实测试原片上传到当前 Work。

收到后：
1. 放入项目约定的 `data/input/` 或等价工作目录。
2. X2-A/B/C 使用**同一份原片**。
3. **整集原片不得提交 GitHub**。
4. 模型权重、缓存、虚拟环境也不得提交。
5. Git 只保存代码、配置、查询、时间码、评测、失败案例、日志、报告和必要的小体积验证产物。

如果云端确实无法读取上传原片，这是少数需要停止并告知用户的情况。禁止用假视频/合成数据代替真实原片后宣布通过。

## 3. 保留 X1 / X2，暂停 Evidence v2 扩展

- **X1 = 素材理解能力**：保留镜头切分、VLM 理解、Evidence；后续可用于候选镜头视觉复核。
- **X2 = 镜头检索能力**：今晚主攻。
- 现有 Evidence 检索继续保留作为基线。
- **暂停继续扩 Evidence v2 字段**，除非失败归因明确证明 Evidence 信息缺失是主要瓶颈。

不要推翻已经跑通的自动剪辑链路。

## 4. 三组 X2 对照实验

### X2-A｜Evidence 基线

```
分镜需求 → Evidence → 语义检索 → Top3
```

冻结当前方案作为 baseline。不要为了提高成绩修改 Gold 或偷偷重写查询。

### X2-B｜Video Embedding

```
分镜需求 → 原始视频/镜头 → Video Embedding → Vector Search → Top3
```

优先实际研究和运行：

- `ssrajadh/sentrysearch`

不要只看 README。追实际调用链：

```
视频切分
→ embedding
→ index/store
→ query embedding
→ similarity search
→ dedupe
→ rerank（若有）
→ source_file + start/end timestamp
```

可以直接运行、复用部分代码，或根据源码实现最小兼容版本。

**目标不是“安装成功”，而是证明/否定原生视频 embedding 对真实影视镜头检索有增益。**

若项目安装成本明显过高或不适合，记录证据后停止，不要为了跑开源项目浪费整晚。

### X2-C｜联合方案（重点）

```
                         ┌→ Evidence Retrieval TopN ─┐
分镜需求 → 检索路由 ────┤                         ├→ 合并/去重
                         └→ Video Embedding TopN ───┘
                                      ↓
                        真实候选视频片段 VLM 复核
                                      ↓
                                  rerank
                                      ↓
                                   Top3
```

VLM 必须查看真实候选视频/候选帧，不能只阅读 Evidence 后自证。

## 5. 按需求类型路由

先识别分镜需求：

- 人物
- 场景
- 动作
- 道具
- 原声台词
- 多条件组合

建议：
- 普通视觉：Evidence + Video Embedding 多路召回。
- 人物：先测试现有路线；失败案例证明必要时再增加人物一致性/人脸通道。
- 场景/道具：语义检索。
- 动作：Video Embedding 粗召回 + 真实短片 VLM 复核。
- 多条件：允许拆条件召回后综合评分，不要求一个 embedding 解决全部条件。

## 6. 原声台词单独处理

不要让视觉检索承担指定原声台词。

```
ASR → 文本检索 → timestamp → 原始音频人工听证
```

可实际研究/运行：
- `modelscope/FunClip`
- FunASR

Q3 示例：“有一种胜利叫撤退，有一种失败叫占领”。

必须定位 ASR 候选和时间码，并实际核对原始音频。**ASR 文本相似不能直接判 PASS。**


## 8. 开发集：Q1–Q5

第一阶段使用现有《潜伏》素材和现有 Q1–Q5。

对 A/B/C 使用完全相同的素材、查询、Top3 口径。

每条候选至少保存：

```
source_file
shot_id
start_time
end_time
score
retrieval_route
```

生成可以直接人工查看的候选短片。

**Q1–Q5 只允许作为开发/诊断集，不得用于宣称最终 ≥90%。**

## 9. 正式盲测

方案稳定后建立至少 **20–30 条未参与调参的新分镜需求**，覆盖人物、场景、动作、道具、台词、多条件组合。

规则：
1. Gold 与检索实现隔离。
2. 不得看到 Gold 后修改 query。
3. Top3 至少 1 个真实满足要求 = 该题成功。
4. 最终成功率 = 成功题数 / 有效盲测题数。
5. 目标 ≥90%。
6. 如果实际 75%、82%、87%，如实报告，不得改统计口径。

20–30 条只能作为本轮 POC 技术验证，不代表生产规模长期准确率。

## 10. 判定原则

最终判定依据必须是**真实原片看片 / 真实原声音频听证**。

禁止：
- Evidence 自证 Evidence；
- VLM 描述自证 VLM；
- embedding similarity 直接证明正确；
- 工程运行成功 = AI 能力成功。

候选标记：
- `exact` 精确命中
- `acceptable_substitute` 可接受替代
- `unusable` 不可用
- `uncertain` 不确定

指定人物、关键剧情事实、关键动作、指定原声原则上必须 exact；“气氛类似”不能算成功。

## 11. 失败归因

保留全部失败。每条至少归入：

1. 原片不存在
2. Evidence 信息缺失
3. Video Embedding 未召回
4. 人物识别错误
5. 动作理解错误
6. ASR/台词错误
7. 正确候选已召回但 rerank 排错
8. 镜头边界/时间码错误
9. 需求本身不可验证
10. 其他

根据失败原因决定优化 X1、召回、rerank 或路由。不要默认继续堆 Evidence。

## 12. 自主执行权限与停损

这是夜间自主任务。除非必须用户授权/登录/付费/提供信息，否则不要停下来等回复。

执行循环：

```
研究 → 实验 → 修改 → 复测 → 比较 → 再修改
```

- 可以自行安装依赖、clone 开源仓库、修改实验代码、运行测试。
- 一条路线连续无增益时，记录结果并及时停止。
- 不以“研究了多少项目”为 KPI。
- 不破坏现有稳定自动剪辑链路；实验代码与稳定代码隔离。
