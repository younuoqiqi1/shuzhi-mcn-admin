# X1.2 50-Shot 全视频批次评测方案与实施计划 (2026-10-06)

## 1. 目标与背景

批次 X1.2 是脱离历史“15 父区间 / 47 children”小范围抽样的全新扩展评测批次。
核心目标是以客观、自动化、无污染的流程，从全视频（2702.013243 秒）中构建全新 50 个独立镜头（共 150 帧，按 25%、50%、75% 提取），并完成镜头切分、去重、抽样冻结、帧提取、VLM 独立沙盒推理、真实报告汇总与人工质检可视化。

## 2. 核心架构与阶段流转 (Stages)

整个流程由 `scripts/x1_2/batch.py` CLI 驱动，分为 7 个严格隔离的 Stage：

```
[detect-window] --> [merge] --> [sample] --> [extract] --> [infer] --> [report] --> [review]
```

### Stage 1: detect-window (滑动窗口镜头切分)
- **视频总时长**: `2702.013243` 秒。
- **窗口策略**: 
  - 每个窗口中心跨度 60.0 秒（例如 `[k*60, min((k+1)*60, 2702.013243)]`）。
  - 两侧各扩展 2.0 秒上下文进行 PySceneDetect 检测（即 `[max(0, k*60 - 2.0), min(total_dur, (k+1)*60 + 2.0)]`）。
  - 检测完成后，**仅保留落在该窗口中心跨度内的切点**，抛弃上下文重叠区域内的切点，避免窗口重叠导致的切点重复或边界干扰。
- **输出格式**:
  - 输出到 `benchmarks/x1/runs/x1_2/windows/window_INDEX.json`（索引为 4 位数字 `window_0000.json` ...）。
  - 每个文件记录：`window_index`, `center_start`, `center_end`, `ctx_start`, `ctx_end`, `cuts`（真实切点绝对秒数列表）, `params`（检测参数、阈值等）, `params_hash`。
- **进程守卫**: 调用 PySceneDetect 或 ffmpeg 切分均受 `55s` 超时硬限制守护。

### Stage 2: merge (全局镜头池构建)
- **纯切点合并**: 仅读取所有窗口输出的真实 cuts，并在全局去重（容差阈值 0.1s）。
- **硬性禁止**: 严禁将 60s 窗口切块边界当作镜头切点添加！
- **镜头池封闭**: 将 `0.0` 和视频终点 `2702.013243` 加入切点列表作为首尾端点，按升序排序后生成所有相邻切点构成的全局镜头候选池 `[(t0, t1), (t1, t2), ...]`。
- **输出**: 保存为 `benchmarks/x1/runs/x1_2/pool.json`。

### Stage 3: sample (冻结分层随机抽样)
- **随机种子**: 固定 `20261006`。
- **三段分层抽样**:
  - 视频全长划分为前、中、后三段：
    - 前段: `[0.0, 900.671081)`
    - 中段: `[900.671081, 1801.342162)`
    - 后段: `[1801.342162, 2702.013243]`
  - 抽样配额: 前段 17 个，中段 17 个，后段 16 个，合计严格 50 个镜头。
- **排除规则 (Exclusion Rules)**:
  - 排除任何与旧 `selected15` 区间发生时间重叠的候选镜头（完全隔离历史数据）。
  - 排除时长过短（< 0.5s）的无效碎片镜头。
- **防人工挑选与盲测匿名化**:
  - 纯程序抽样，严禁人工按画面挑选镜头；若候选池不足 50 个直接报错阻断，禁止复制填充。
  - 镜头统一匿名重命名为 `shot_B0001` ~ `shot_B0050`。
  - 硬 Guard：抽样逻辑完全不读取 gold 标注、旧 Evidence 或任何剧情上下文。
- **冻结 Manifest**:
  - 输出 `benchmarks/x1/runs/x1_2/manifest.json`。
  - 包含全局 SHA256、随机种子、排除原则记录、50 个镜头的元数据（起止时间、段落位置、匿名 ID）。生成后即冻结，后续步骤不重新抽样。

### Stage 4: extract (多点切帧提取)
- **切帧点位**: 每个镜头按相对时长提取 25%、50%、75% 三处关键帧，共计 150 帧。
- **原图保持**:
  - 直接提取原视频分辨率真实 JPG 帧（禁用任何 crop/pad 变形缩放）。
- **元数据与哈希**:
  - 记录每帧精确视频时间戳 `timestamp_sec`。
  - 计算并记录 JPG 文件的 SHA256 哈希值。
- **守卫机制**:
  - ffmpeg 进程受 `55s` lifecycle 进程组控制，超时立即 `killpg` 清理。

### Stage 5: infer (VLM 隔离推理)
- **调用粒度**: 命令行支持 `--shot-id` 与 `--pct 25|50|75` 精确控制，也支持批处理全量运行。
- **Prompt 规范**:
  - 模型：`gemini-3.1-pro-low`（`effort=low`，384 分辨率规范，经由原生 `AGYCLIGeminiProvider` 结构化请求输出）。
  - 视觉提示词中显式约束：`screen-left/right avoid anatomical when mirrored`（统一使用屏幕左/屏幕右，避免镜像造成的解剖学左右歧义）。
- **沙盒隔离与防污染**:
  - 每次推理以单张图片为沙盒运行。
  - 原生 stream 轨迹移动转存至 `benchmarks/x1/runs/x1_2/streams/`，不冒充其他批次。
  - 严禁推理过程读取任何 human labels、gold 预测输入或剧情上下文，仅依赖当前图像与基础 manifest。
- **输出格式**:
  - 每帧保存独立 JSON：包含 `shot_id`, `pct`, `source_hash`, `infer_hash`, `model`, `latency_ms`, `usage`, `raw_response`。
  - 绝对禁止本地假推理或重新下载。

### Stage 6: report (客观真实汇总报告，由独立 review_report.py 执行)
- **独立执行器**: 由独立的 `scripts/x1_2/review_report.py --action report` 执行，严格调用 `scripts.x1_1.vlm_schema.validate_vlm_output`（6 核心字段完整性）与 `scripts.x1_1.assemble_report.verify_stream_log` 进行原生 Stream 审计。
- **统计分母**: 以完整的 `50 * 3 = 150` 尝试为绝对分母。
- **错误处理**: 若发生模型 503 或网络失败，第一轮不重试，按真实失败计入统计。
- **真实覆盖率与真值隔离**:
  - 50 个全新镜头绝不复用旧 15 ASR 作为音频真值。
  - 文本 OCR 可在重叠情况下挂载现有硬字幕快照，但缺失 ASR 的部分必须显式标记为 `pending`。
  - 报告仅汇总真实推断成功率与覆盖率，严禁伪造 Person F1 或伪造完整 Gold 指标。

### Stage 7: review (人工质检与独立标注，由独立 review_report.py 执行)
- **独立执行器**: 由独立的 `scripts/x1_2/review_report.py --action review` 生成。
- **独立成果物**: 输出 `/Users/yoyotaozhou/Documents/antigravity/intelligent-pasteur/artifacts/x1_2-review/review.html`。
- **界面功能**:
  - 150 帧内嵌 384 推理缩略图与可折叠原图。
  - 按镜头分组排列，显示起止时间与秒数，方便比对左/右方位。
  - 支持可选 `--clips-dir` 内嵌 50 shot 轻量切片视频（仅供人工复核边界与听音，不送 VLM）。
  - 人工标签表单默认留空（无预设默认值，边界可用性选择未填写导出为 null，防止确认偏差）。
  - 导出的独立 Gold 标注仅供后续评测评估模块读取，推理模块绝对无法访问。

## 3. 进程管理与安全清理规范
- 任何外部进程（PySceneDetect / ffmpeg / CLI runner）必须通过独立进程组启动：`preexec_fn=os.setpgrp`。
- 超时或脚本退出时，通过 `os.killpg(os.getpgid(p.pid), signal.SIGTERM)` 强制终止，并在等待后发送 `SIGKILL` 彻底防止僵尸进程。
- 注册 `atexit` 与信号处理器（SIGINT, SIGTERM）保证环境整洁。
